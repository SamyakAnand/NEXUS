# NEXUS Project Audit

**Audit date:** 2026-10-05  
**Scope:** Repository implementation and configuration in the current checkout. This is a code audit, not an independent penetration test or production load test.

## Executive summary

NEXUS is a working portfolio analytics prototype. The Next.js client calls a FastAPI service for dataset listing, upload, analysis, traces, and report generation. The backend profiles tabular records and computes deterministic summaries, grouped SQL aggregates, correlation, Isolation Forest outlier flags, basic linear trend extrapolation, chart data, evidence-linked findings, and Markdown reports. Analysis planning and synthesis are deterministic Python logic. LangGraph is present as an optional graph runtime, but no LLM provider is initialized or called.

The repository also contains PostgreSQL/pgvector schema and Docker services, but the API currently stores dataset metadata, uploaded files, and runs in a JSON manifest/files and in-process dictionaries. It does not persist to PostgreSQL, Redis, or pgvector. On Vercel the file store points to `/tmp/nexus-data`, so uploaded datasets and saved runs are ephemeral and instance-local. There is no implemented authentication or tenant isolation. Do not use the deployed prototype for sensitive or multi-user data.

## Current execution flow

1. The frontend calls `/api` endpoints through `apps/web/src/lib/api.ts`.
2. FastAPI restores a JSON manifest and run JSON files from its configured data directory, creates a synthetic demo CSV when absent, and holds active frames/runs in process memory.
3. Uploads are limited by `MAX_UPLOAD_MB` (default 15 MiB), parsed as CSV, XLSX, or JSON, and profiled.
4. `_tool_plan` chooses deterministic tools from question keywords. `_choose_metric` and `_choose_group` infer fields by literal names/hints.
5. The analysis core runs selected deterministic computations, records a trace, assembles findings, and performs basic evidence-presence validation. If LangGraph imports, the same deterministic core is invoked through a conditional graph. If import fails, direct execution is used.
6. The response is stored as a JSON file and in process memory; chart output is rendered by the web app and reports are assembled as Markdown.

There is no provider call at the planner, execution, validation, or synthesis stages. `insight_synthesis` is a deterministic concatenation of finding details. The graph therefore exists, but its reasoning layer is not an LLM.

The Vercel service routing makes both `/api/*` and the web catch-all public. No service-to-service binding is required by the current implementation: the browser calls the public `/api` route, and the Next.js rewrite is disabled when `VERCEL` is set. Docker’s web container uses `BACKEND_URL=http://api:8000` for local proxying.

## Risks and gaps

- **Ephemeral deployed data:** Vercel `/tmp` storage and per-instance dictionaries are not durable or shared across serverless instances. Uploads/runs can disappear or be unavailable to another invocation.
- **No access control:** datasets and analysis endpoints are unauthenticated; the deployed API is publicly routed.
- **No tenant isolation or retention controls:** no user ownership model is connected to requests.
- **No LLM despite AI branding/dependencies:** LangGraph is installed, but deterministic routines do all planning and synthesis. OpenAI is not configured or called.
- **No actual RAG:** pgvector DDL and retrieval metric fixtures do not constitute embeddings or vector retrieval.
- **Validation scope:** validation confirms structural/evidence conditions, not whether every statistical conclusion is appropriate or causally valid.
- **Forecast limitations:** linear extrapolation is a basic illustration, without seasonality handling or uncertainty intervals.
- **Upload safety/performance:** size and extension checks exist, but no isolated parser worker, decompression/CPU budget, concurrency control, or deployment load evidence was found.
- **CI is configured:** the local API tests, TypeScript check, and production build passed in this checkout; GitHub Actions itself was not inspected live or run remotely.
- **Product copy/UI may imply more autonomy than implemented:** keep deterministic mode, demo data, lack of persistence, and provider status explicit in user-facing claims.

## UX and architecture findings

- The current workspace is a single analysis canvas with dataset, finding/evidence, chart/schema visualization, and trace views. It is not yet a multi-page dashboard with global filters, cross-filtering, or drill-down.
- The landing page's live demo is backed by API output; the 3D dataset schema view is backed by the active dataset profile. These are functional visualizations, while the animated landing scenes are presentation elements.
- The audit found an inaccurate workspace privacy note and stale GitHub footer. The follow-up audit cleanup now says files are sent to the NEXUS API for processing and links to the actual GitHub repository. Hosted Vercel uploads still use ephemeral `/tmp` storage; the interface should communicate its retention behavior more explicitly.
- “Agent traces” and “LangGraph workflow” are observable deterministic stages, not evidence of an LLM agent. Keep that distinction visible in product language.
- Responsive styles, labels, and a WebGL fallback exist in source. A full keyboard, screen-reader, contrast, mobile-device, and browser compatibility review was not performed.

## Maturity assessment

**Portfolio prototype / early proof of concept.** The product has an end-to-end browser-to-API workflow and useful deterministic analysis primitives. No subsystem was established as production-ready for sensitive, collaborative, durable, or high-volume workloads. Core production prerequisites include authentication and authorization, durable shared persistence, deployment-safe job execution, reliable data cleaning controls, stronger validation, operational limits/observability, and end-to-end deployment verification. Real LLM and RAG functionality are separate product capabilities and remain unimplemented.

## Recommended next step

Treat this audit as the baseline. Before describing NEXUS as an autonomous LLM analyst or production platform, prioritize deployment correctness and trustworthy data handling: establish durable persistence and user access controls, define a safe/inspectable cleaning workflow, and verify the live Vercel browser → API → data → response path. Add provider-backed LLM planning/synthesis only as a separately configured, observable capability with deterministic mode still clearly identified. Add real embeddings/vector retrieval only when a concrete metadata retrieval use case and evaluation set are defined.
